## Уровни сложности

### Уровень 1 — Базовые таймеры (задания 1–3)

**Цель**: освоить `setTimeout`, `setInterval`, `clearTimeout`, `clearInterval`.

**Концепции**:
- Отложенный вызов функции через `setTimeout`
- Повторяющийся вызов через `setInterval`
- Отмена таймера через `clearTimeout` / `clearInterval`
- Возврат `timerId` для последующей отмены

**Пример**: после создания карты уведомление появляется не мгновенно,
а с небольшой задержкой — это `setTimeout`.

---

### Уровень 2 — Управление таймерами (задания 4–7)

**Цель**: научиться контролировать жизненный цикл таймеров.

**Концепции**:
- Обратный отсчёт (countdown) с `setInterval`
- **Debounce** — вызов только после паузы в вводе
- **Throttle** — ограничение частоты вызовов
- Автоочистка данных через таймер

**Чем debounce отличается от throttle**:

```
DEBOUNCE: ждёт паузу
пользователь печатает:  A  B  C  ...пауза...  D
запрос отправляется:                           ↑

THROTTLE: пропускает лишние вызовы
события scroll:  ↓  ↓  ↓  ↓  ↓  ↓  ↓
обработчик:      ↓           ↓           ↓
                 ^-- первый  ^-- через interval
```

---

### Уровень 3 — Продвинутые паттерны (задания 8–11)

**Цель**: комбинировать таймеры с промисами и состоянием.

**Концепции**:
- Автообновление: немедленный запрос + `setInterval` + защита от дублирования
- Отменяемый debounce (нужен при размонтировании компонента)
- Очередь с задержкой между элементами
- `setInterval` внутри `Promise` (ожидание условия)

**Ключевая ловушка в задании 8** — двойной запуск:

```javascript
// ПЛОХО — createAutoUpdater без защиты
updater.start();
updater.start(); // теперь 2 интервала, данные грузятся вдвое чаще!

// ХОРОШО — проверяем что таймер ещё не запущен
function start() {
  if (timerId !== null) return; // защита
  // ...
}
```

### Уровень 4 — Сложные сценарии (задания 12–14)

**Цель**: реализовать полноценные production-паттерны.

**Концепции**:
- Композиция таймеров (кулдаун + блокировка + флаг загрузки)
- Динамический `setTimeout` вместо `setInterval` (интервал меняется)
- Дедупликация через объект-словарь с TTL

**Почему в задании 13 используется `setTimeout`, а не `setInterval`**:

```javascript
// setInterval — интервал ВСЕГДА одинаковый
setInterval(fetchFn, 1000);

// setTimeout — следующий запрос планируется ПОСЛЕ завершения текущего,
// и интервал может быть разным (normalInterval vs errorInterval)
async function runOnce() {
  try {
    await fetchFn();
    setTimeout(runOnce, normalInterval);  // успех → обычный интервал
  } catch {
    setTimeout(runOnce, errorInterval);   // ошибка → длинный интервал
  }
}
```

## Типичные ошибки

### ❌ Забыть очистить таймер

```javascript
// ПЛОХО — интервал продолжает работать после ухода со страницы
function startPolling() {
  setInterval(fetchData, 1000);
  // нет stop()!
}
```

```javascript
// ХОРОШО — всегда возвращаем возможность остановить
function startDataPolling(fetchData, intervalMs) {
  const id = setInterval(fetchData, intervalMs);
  return { stop: () => clearInterval(id) };
}
```

---

### ❌ Запустить два интервала вместо одного

```javascript
// ПЛОХО — двойной запуск
updater.start();
updater.start(); // два интервала!
```

```javascript
// ХОРОШО — проверяем флаг
function start() {
  if (timerId !== null) return;
  // ...
}
```

---

### ❌ Не сбросить таймер в debounce

```javascript
// ПЛОХО — предыдущий таймер не отменяется
function debounce(fn, delay) {
  return function() {
    setTimeout(fn, delay); // накапливаются!
  };
}
```

```javascript
// ХОРОШО — отменяем предыдущий перед созданием нового
function debounce(fn, delay) {
  let timerId = null;
  return function(...args) {
    clearTimeout(timerId); // отменяем старый
    timerId = setTimeout(() => fn(...args), delay);
  };
}
```
